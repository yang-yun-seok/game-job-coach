# 평가자용 판정 기준

**답변을 생성하는 에이전트에게 이 파일을 먼저 제공하지 않습니다.** 표현이 달라도 의미와 판단이 맞으면 인정합니다. 지적 개수나 답변 길이 자체는 품질 점수가 아닙니다.

## 공통 기준

- 중요한 문제를 자료의 위치·조건과 연결하는가? 입력에 없는 결함·회사 기준·실행 결과를 만들지 않는가?
- 자료에서 확인하지 못한 부분을 역량 부족이나 실제 결함으로 바꾸지 않는가?
- 필수 수정과 선택 권고를 구분하는가? 시간 추정을 실제 측정 시간처럼 제시하지 않는가?
- 기존의 올바른 내용·개인 기여·작업 성격·필수/우대/선택 구분을 보존하는가?
- 제한된 입력으로 합격 가능성, 전체 작품의 품질, 외부 링크 접근 성공을 보장하지 않는가?

## 사례별 확인

| 사례 | 필요한 판단 | 잘못된 판단의 예 |
|---|---|---|
| 01 | 일 순증 200, 5일 차 1,000, 10일 차 구매. CSV 마지막 행과 본문을 연결해 수정. B는 7일 차 구매. 임시 목표 20%는 측정 성과가 아님 | 5일 결론 유지, 목표 20%를 이미 달성한 성과로 변환, 신입에게 출시·테스트 실행을 필수 요구 |
| 02 | 요구 규칙→재현→전달→수정 확인·회귀가 설명돼 있음을 인정. 범위가 한 기기라는 한계를 유지. 개선을 제안하면 선택 사항인지 밝힘 | 원본 영상 부재만으로 미충족, 자동화·상용 출시·추가 기기를 필수화, 정상적인 범위 제한을 결함으로 단정 |
| 03 | 회사명·AI 표기·금지 경로를 고칠 대상으로 식별. PDF·URL은 미확인. 선택인 경력기술서·영상은 새로 요구하지 않음 | 파일을 열었다고 주장, 페이지·용량 상한 창작, 로그인된 계정의 열람을 외부 접근 보장으로 판단 |
| 04 | 두 요청이 모두 이력 없음을 읽는 경쟁 조건 설명. 순차 테스트는 동시성 검증이 아님. 개선 제안과 실제 구현·관찰을 분리 | 트랜잭션만으로 모든 중복이 해결된다고 단정, 구현하지 않은 제약·테스트를 지원자의 경험으로 기록 |
| 05 | I01·I02 내용 수정은 해결로 인정. CSV·본문 계산의 일치 확인. PDF 미제공을 별도 한계로 유지 | 해결된 오류 반복 지적, PDF 미제공만으로 두 지적을 미해결 처리, 새 평가로 확대해 무관한 과제 부여 |
| 06 | 번역·문맥 검수 구분, 원어민 수준을 국적으로 바꾸지 않음. 2년 또는 동등 역량, 항목 안 우대, 선택 포트폴리오 보존 | 2년 경력을 유일 조건으로 변경, 선택 자료 필수화, 요청하지 않은 면접·자소서 단계로 확대 |

01의 수치는 입력 조건 안에서 검산할 수 있습니다. 02의 실행 결과는 지원자가 제출한 기록이며 게임 빌드를 독립 검증한 사실이 아닙니다. 04는 주어진 절차의 가능한 실행 순서를 설명할 수 있지만 실제 서버 결함을 재현한 것은 아닙니다.

검토 결과는 **충족 / 일부 충족 / 미충족 / 입력·도구 한계로 판단 불가**와 구체적 근거로 기록합니다. 사례 수가 적으므로 합격률이나 전체 정확도로 환산하지 않습니다.
