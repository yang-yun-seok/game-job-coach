# QA 서류 검토

자체 작성한 가상 사례입니다. 실제 회사·지원자 자료가 아닙니다.

## 사용자 요청

게임 QA 신입 지원 전에 이 한 페이지를 냉정하게 봐주세요. 오늘 30분 더 고칠 수 있습니다. 답변은 800자 이내로 부탁드립니다.

## 가상 공고

모바일 게임 기능 테스트, 재현 가능한 이슈 보고, 수정 확인과 회귀 테스트를 담당합니다. 신입 지원 가능. 필수는 테스트 의도와 결과를 설명하는 능력, 개발팀과의 의사소통입니다. 자동화 경험은 우대이고, 프로그램 작성이나 출시 경험은 필수가 아닙니다. 회사가 지정한 보고서 양식은 없습니다.

## 지원자 보고서

개인 학습용 상점 빌드에 수행한 수동 테스트입니다. 본인은 테스트 설계·실행·보고만 맡았습니다. 기능 구현과 패치는 협업한 개발자가 담당했습니다.

- 요구 규칙 R1: 재화가 부족하면 구매 거절, 잔액과 아이템 수는 유지.
- 범위: Android 14의 개인 보유 기기 1대, 테스트 빌드 0.3.1. 다른 기기 호환성·성능·결제는 검증하지 않음.
- 케이스 Q1: 잔액 100, 가격 80, 보유 0 → 구매 1회 → 기대 잔액 20·보유 1, 실제 일치.
- 케이스 Q2: 잔액 79, 가격 80, 보유 0 → 구매 1회 → 기대 거절·잔액 79·보유 0, 실제 잔액 -1·보유 1. 동일 초기화 후 3/3 재현. 재화 부족 제한을 우회하므로 기능 차단 수준으로 제안. 원인은 개발팀 확인 전 미정.
- 전달: 환경, 초기 상태, 절차, 기대/실제, 재현 횟수와 R1을 개발자에게 전달. 개발자가 수정 빌드 0.3.2 제공.
- 재검증: 같은 기기·초기 상태에서 Q2 3회 모두 기대와 일치. Q1과 잔액 80의 경계 사례도 기대와 일치. 빌드 0.3.2의 보고서 범위에서 해결로 기록.
- 근거 위치: 본 페이지 각 케이스. 원본 영상과 빌드는 이번 대화에 미제공. 이는 지원자가 제출한 기록이며 외부 검증을 받았다는 주장은 없음.

공고에 없는 항목까지 새로 만들 시간을 쓰기보다 제출에 도움이 되는 판단을 원합니다.
