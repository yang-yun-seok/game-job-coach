# 서버 면접 답변 검토

자체 작성한 가상 사례입니다. 실제 회사·지원자 자료가 아닙니다.

## 사용자 요청

서버 개발 신입 모의 면접 답변을 기술적으로 검토해주세요. 새로운 면접을 시작하지 말고 가장 중요한 보완점을 알려주세요. 700자 이내로 답해주세요.

## 공고와 질문

가상 공고의 업무는 보상 지급 API와 데이터 무결성 관리입니다. 질문은 '중복 보상 요청에 어떻게 대응했나요?'입니다.

## 지원자의 실제 답변

개인 프로젝트에서 보상 중복 지급을 막았습니다. 각 요청은 별도 연결로 `SELECT`해서 지급 이력이 없으면, 잔액을 올리고 지급 이력을 `INSERT`합니다. 각 SQL 문은 자동 커밋이며 트랜잭션, 잠금, 유일성 제약, 요청 키는 사용하지 않았습니다. 순서대로 두 번 요청하면 두 번째가 거절되는 것을 확인했습니다. 그래서 동시에 들어오는 요청도 중복 지급되지 않는다고 판단했습니다. 상용 서비스에는 적용하지 않았습니다.

코드 전체와 동시 요청 실행 로그는 제공하지 않았습니다.
