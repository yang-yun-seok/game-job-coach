# 실용성 점검과 수정 기록

확인일: **2026-11-03** · 수정 전 기준 커밋: `80e934994dd64a04043f6ee15bcfaa59005d86a7`

이번 수정의 목적은 기능 수를 늘리는 것이 아니라, 확인된 오류·누락을 우선하고 충분한 자료에는 불필요한 수정을 요구하지 않도록 하는 것이다. 실제 취업 효과나 합격률을 입증한 실험은 아니다.

## 확인한 현실의 조건

- [네오플 던전 콘텐츠 기획 공고](https://careers.nexon.com/recruit/6878)의 본문에는 포트폴리오 유형과 제출 경로가 지정돼 있으며 Google Drive 제출은 열람할 수 없다고 안내돼 있다. 이는 내용 첨삭뿐 아니라 실제 접수 조건을 확인해야 할 이유가 된다.
- [넥슨 슈터플랫폼실 웹서비스 기획 공고](https://careers.nexon.com/recruit/10038?jobCategories=4)는 AI 사용 범위와 직접 기획·설계한 부분을 구분해 설명하도록 안내한다. 해당 문구는 우대 사항 영역에 있으므로 별도 명시 없이 채용 자격의 필수 조건으로 재분류하지 않는다.
- [Riot의 포트폴리오 안내](https://www.riotgames.com/en/portfolio-and-reel-suggestions)는 작업물 선별, 접근 가능 여부, 제작 과정·기여를 설명한다. 특정 회사의 안내이며 국내 게임사 전체의 공통 심사 기준으로 사용하지 않는다.

위 자료는 코칭 항목이 실제 채용과 관련 있다는 근거다. 이 스킬이 일반 답변보다 낫다거나 채용 성과를 높인다는 증거는 아니다. 넥슨 두 공고는 일반 웹 추출에서 본문이 비어 브라우저의 실제 본문을 확인했다. 공고는 이후 변경될 수 있다.

## 방법

1. 공개 가능한 가상 입력을 자체 작성했다. [경제 기획](../tests/cases/01-economy.md), [QA](../tests/cases/02-qa.md), [제출 준비](../tests/cases/03-submission.md), [서버 면접](../tests/cases/04-interview.md)을 같은 내용과 분량 제한으로 비교했다.
2. 새 에이전트 하나는 스킬 없이, 다른 하나는 수정 전 스킬과 필요한 참조를 사용했다. 각 에이전트가 네 요청을 개별 사례로 처리했으며, 기대 답안이나 상대 출력은 제공하지 않았다. 따라서 사례별 반복 실험이나 통계적 비교가 아니다.
3. 수정본은 별도의 에이전트들로 01~06을 점검했다. 05는 수정본 검토, 06은 공고 해석 범위를 확인하는 추가 사례다. 06은 기존 스킬로도 별도 확인했다. 01의 최종 판정은 수정본 예시 05를 읽지 않은 새 에이전트의 재실행 결과를 사용했다.
4. 입력의 수치·조건과 [판정 기준](../tests/expectations.md)을 사람이 읽을 수 있는 결과에 대조했다. 자동 채점이나 현업 전문가의 독립 심사는 아니다. 실행 환경은 Codex의 이 대화와 독립 에이전트이며, Claude에서는 실행하지 않았다.

## 수정 전 비교에서 확인한 점

| 사례 | 일반 답변과 기존 스킬의 공통 결과 | 판단 |
|---|---|---|
| 01 경제 기획 | 5일 차 잔액 1,000, 첫 구매 10일을 계산하고 CSV·본문 오류를 지적. 임시 목표와 실행 성과를 구분 | 핵심 계산 검토는 이미 가능. 새 능력을 얻은 것으로 계산하지 않음 |
| 02 QA | 제출 기록의 강점과 범위 한계를 인정. 자동화·상용 출시·영상의 필수화를 피함 | 치명적 오판은 관찰되지 않음. 기존 답변은 30분 수정 계획을 배정해 선택적 다듬기의 필요성이 덜 분명했음 |
| 03 제출 준비 | 회사명·AI 표기·금지된 링크 경로를 식별. PDF·URL 미확인과 선택 자료를 구분 | 새 점검 지침이 없어서 못 하던 작업은 아님. 조건부 절차로 모아 재사용성을 높임 |
| 04 서버 면접 | 조회 후 지급의 경쟁 조건과 부분 반영 가능성을 설명. 개선 설계와 실제 경험을 구분 | 추가 기술 평가 규칙의 필요성이 확인되지 않아 해당 수정안은 제외 |

기존 스킬로 추가 확인한 06도 경력 대체 조건과 선택 제출을 보존했고, 면접 질문을 덧붙이지 않았다. 공고 분석의 기본 면접 질문 5개 지침은 관찰된 오답의 수정이 아니라 요청 범위와 충돌할 여지를 없애는 정리로 바꿨다.

## 반영한 변경

- 다음 행동을 최대 3개로 **묶되**, 필수 누락을 숨기거나 개수를 채우려고 지적하지 않도록 했다. 확인된 문제와 선택적인 표현 개선을 구분하고, 충분한 부분은 유지한다.
- 서류 검토의 지적을 위치·근거·영향·가장 작은 보완·완료 기준으로 연결한다. 구성 제안은 요청할 때만 제공하고 보편적인 페이지 수를 강제하지 않는다.
- [제출 점검](../game-job-coach/references/submission-check.md)을 기존 서류 작업의 조건부 참조로 추가했다. 실제 접수 조건, 최종 파일, 외부 열람, AI·협업 관련 안내를 제공 자료에 맞춰 대조한다.
- 공고 해석만 요청했을 때 기본 면접 질문을 추가하던 지침을 제거했다. 기술 면접·지원 결과 복기·과제전형의 새 모드는 만들지 않았다.

## 수정 후 확인

| 사례 | 관찰 결과 | 한계 |
|---|---|---|
| 01 경제 기획 | 계산 오류의 위치와 최소 수정, 역할·학습 범위와 미확인 부분을 구분 | 텍스트·CSV 검토이며 실제 PDF·플레이 품질 평가는 아님 |
| 02 QA | ‘오늘 반드시 고칠 내용상 오류는 보이지 않습니다’라고 판단하고 요약 문장은 선택 사항으로 제안 | 한 사례의 변화이며 전반적인 잘못된 지적 감소율을 뜻하지 않음 |
| 03 제출 준비 | 세 가지 명시 문제를 우선하고 기존 기여 표기·선택 제출을 유지. 최종 파일과 열람 상태는 미확인으로 남김 | 실제 PDF 렌더링이나 외부 링크 권한을 검증한 사례는 아님 |
| 04 서버 면접 | 순차 테스트의 한계와 경쟁 조건을 설명하고 미구현 개선안을 경험으로 바꾸지 않음 | 실제 서버 코드 실행·동시성 재현은 하지 않음 |
| 05 수정본 | CSV와 본문을 대조해 I01·I02 해결을 인정하고 추가 내용 수정이 필요 없다고 답함 | 두 지적에 한정한 내용 검토이며 최종 파일 확인은 별개 |
| 06 현지화 공고 | 대체 경력·원어민 수준·선택 제출을 보존하고 공고 해석 범위를 유지 | 가상 본문이며 실제 웹 접근 검증은 아님 |

여섯 사례에서 위의 핵심 판정 조건을 확인했다. 독립 에이전트 수를 현업 전문가 수로 표현하지 않으며, 한 번의 성공을 안정적인 정확도나 일반 모델 대비 우위로 환산하지 않는다.

## 아직 확인하지 못한 것

실제 지원자의 수정 소요 시간과 만족도, 현업 검토자의 평가, 서류·면접 통과율은 측정하지 않았다. 실제 PDF·이미지·음원·실행 빌드를 포함한 검증과 Claude 환경 점검도 남아 있다. 따라서 이번 변경은 **코칭 범위를 좁히고 확인 가능한 결과를 분명하게 하는 개선**이며, 채용 경쟁력이나 전문 심사의 정확성을 보장하는 업그레이드라고 소개하지 않는다.
