# 현지화 직무의 근거를 읽는 관점

회사 공고의 언어쌍·지역·담당 업무·경력 수준을 우선한다. 아래는 코칭용 제안 기준이며 회사의 공식 평가표나 업계 공통 채용컷이 아니다.
번역·감수, 현지화 PM, LQA는 서로 다른 책임이다. 같은 번역 샘플을 문장 품질·일정 관리·결함 검출의 동일한 증거로 쓰지 않는다.
공고가 없으면 특정 언어·지역·자격증·원어민 조건·장르·문체·CAT 툴·처리 단어 수를 임의로 요구하지 않는다. 목표가 불분명하면 현재 자료의 확인 범위를 먼저 제시한다.
개인 번역·비공식 재번역·학습 프로젝트·모의 일정 관리·공개 빌드 점검도 근거가 된다. 실제 계약·납품·출시·지역 성과와 구분한다.

## 공통 확인과 관찰 한계

- `원문·맥락·자료 위치 → 본인 작업 → 선택·검수 → 관찰 결과 → 한계`로 판단을 연결한다.
- 원문, 공식 번역, 참고 번역, 본인 초안·수정안, 공동 감수, 기계 번역·생성 도구 사용 범위를 구분한다. 공식 번역의 성과를 본인의 성과로 쓰지 않는다.
- 원문·목표어·맥락을 확인하지 못했다면 정확성·자연스러움·용어 적합성 판단을 제한한다. 해당 언어를 충분히 검토할 수 없다면 품질 확정을 유보한다.
- 화면을 직접 보지 못했다면 잘림·겹침·렌더링·상황 적합성은 유보한다. 음성을 듣지 못했다면 발음·음성 일치의 품질을 평가하지 않는다.
- 역번역만으로 최종 문장의 자연스러움을 검증했다고 하지 않는다. 스타일 가이드나 용어집이 없으면 표현 차이가 오류인지 선호 차이인지 구분한다.
- 기밀 원문·미공개 빌드·번역 메모리·고객 용어집·개인정보 공개를 요구하지 않는다. 허용된 발췌·익명화한 사례·사용 권리가 확보된 개인 샘플을 활용한다.
- 공개할 수 없는 자료는 미확인 범위로 남긴다. 자료를 볼 수 없다는 이유를 곧바로 업무 경험 부재나 공고 미충족으로 바꾸지 않는다.
- 품질 개선·일정 단축·오류 감소 수치는 분모·기간·비교 조건·본인 기여가 확인될 때 사용한다. 가상 수치는 실제 프로젝트 실적으로 쓰지 않는다.

## 번역·감수

- 담당 결과물: 공고가 정한 언어쌍의 게임 텍스트 번역·수정, 용어·문체 기준, 질의와 감수 기록. 번역자와 최종 승인자의 권한을 구분한다.
- 관찰 증거: 허용된 원문·맥락·목표어, 문자·플레이 제약, 번역 선택 이유, 용어 일관성, 감수 의견과 반영 전후, 확인이 필요한 질의.
- 공고가 품질 기준 수립·평가 또는 AI 번역 개선을 맡기면, 본인이 작성·갱신한 용어집·스타일 가이드와 평가 기준, 오류 분류·언어 피드백의 반영 범위를 확인한다.
- 좋은 근거: 같은 단어의 의미가 맥락에 따라 달라지는 경우를 식별하고, 캐릭터 말투·플레이 기능·용어 기준에 맞춰 선택을 설명한다.
- 좋은 근거: 감수는 오역·누락·일관성 문제와 취향에 따른 수정을 구분하며, 무엇을 왜 고쳤는지 원문·규칙·맥락에 연결한다.
- 부족한 근거: 외국어 자격·체류 경험은 관련 경험일 수 있으나 게임 번역 품질 전체를 입증하지 않는다. 긴 번역 분량만으로 정확성·일관성을 판단하지 않는다.
- 부족한 근거: 원문 없는 완성 문장이나 공식 번역과의 단순 차이만으로 오역을 확정할 수 없다. 원문 자체의 오류·정보 부족 가능성도 확인한다.
- 보완 행동: 대표 구간에 원문·상황·본인 번역·선택 근거와 질의를 붙인다. 기존 번역 수정은 참고 원문과 본인의 변경 부분을 구분한다.
- 보완 행동: 본인 자료 안의 실제 용어·문체 문제를 찾아 수정하고, 같은 표현이 쓰인 다른 구간도 확인한다. 검토하지 않은 부분은 표시한다.
- 완료 기준: 선택한 구간의 원문과 번역이 대응하고, 핵심 용어·말투·플레이 제약에 대한 판단과 미확정 질의가 추적된다. 수정 이유는 규칙·맥락 또는 명시한 가정으로 설명된다.
- 완료 기준: 감수 효과를 주장하면 전후 문장과 재검토 범위가 있어야 한다. 개인 샘플은 평가 가능한 번역 사례이며 전문 납품 경험으로 표시하지 않는다.
- 면접 질문: “자연스러움과 기능상 정확성이 충돌한 문장을 어떻게 해결했나요?”, “원문 맥락이 부족할 때 어떤 질문을 먼저 하나요?”
- 면접 질문: “오류 수정과 문체 선호를 어떻게 구분했나요?”, “기계 번역을 사용했다면 어떤 부분을 어떤 방법으로 검토했나요?”

## 현지화 PM

- 담당 결과물: 범위·일정·리소스·의존성·버전·질의·품질·납품 흐름 관리 중 공고가 맡긴 영역. 번역 품질 판단과 일정·조정 책임을 분리한다.
- 관찰 증거: 작업 범위와 언어별 단계, 담당자·승인 경로, 원문 확정·변경 관리, 질의·결함 추적, 납품 확인, 일정 변경과 대응 기록.
- 좋은 근거: 번역→감수→빌드 적용→검수의 실제 의존성을 파악하고, 변경이 생겼을 때 영향 범위와 선택 가능한 대응을 이해관계자에게 전달한다.
- 좋은 근거: 지연·누락·재작업 문제의 원인과 본인 조치, 협의 결과·잔여 위험을 구분한다. 자신에게 없던 예산·계약·승인 권한을 맡았다고 쓰지 않는다.
- 부족한 근거: 언어 능력이나 번역 샘플만으로 일정·버전·외주 관리 역량을 입증하지 않는다. 참여 언어 수·프로젝트 이름만으로 조정 난도나 기여를 확정하지 않는다.
- 부족한 근거: 계획표가 있다는 사실은 실제 실행 결과와 다르다. 일정 준수율만 제시하면 범위 변경·품질·초기 계획의 적정성은 확인하기 어렵다.
- 보완 행동: 대표 사례의 범위·일정·의존성과 실제 변경 하나를 정리하고, 본인이 파악·제안·결정·확인한 부분을 분리한다.
- 보완 행동: 실무 사례가 없다면 제한된 개인 프로젝트로 원문 변경→재작업 대상 식별→검수→납품 확인을 설계하거나 실행하고 각각의 상태를 표시한다.
- 완료 기준: 변경된 항목이 어떤 작업·담당자·일정에 영향을 주는지 추적할 수 있고, 전달 내용·승인 주체·최종 확인과 미해결 위험이 구분된다.
- 완료 기준: 모의 프로젝트라면 산출물·가정·실행한 범위가 명시된다. 미실행 일정과 가상 비용을 실제 관리 성과로 제시하지 않는다.
- 면접 질문: “원문이 마감 직전에 바뀌면 무엇부터 확인하나요?”, “일정을 지키기 위한 대안과 품질 위험을 어떻게 전달했나요?”
- 면접 질문: “누가 최종 승인하며 구버전 파일 납품을 어떻게 막았나요?”, “업체 또는 팀과 의견이 달랐을 때 본인의 결정 권한은 어디까지였나요?”

## LQA·언어 품질 검수

- 담당 결과물: 적용된 번역·문화적 맥락·표시·언어 설정 관련 결함의 발견·보고·수정 확인. 일반 기능 QA와 겹치는 부분은 있지만 같은 직무로 취급하지 않는다.
- 관찰 증거: 빌드·플랫폼·로케일, 문자열·화면 위치, 원문·기대 기준·실제 결과, 재현 절차·스크린샷, 영향 판단·수정 확인·회귀 범위.
- 좋은 근거: 맥락 오역·누락·일관성·문자 표시·길이 문제를 근거와 함께 보고하고, 언어 문제·자산 문제·기능 문제 중 원인이 미확정인 부분을 구분한다.
- 좋은 근거: 수정 문구가 적용됐는지뿐 아니라 해당 화면과 관련 표현에서 문제가 해소됐는지 확인하고, 재현되지 않거나 검수하지 못한 조건을 남긴다.
- 부족한 근거: 버그 발견 건수만으로 정확성·영향 판단·추적 역량을 평가하지 않는다. 기능 테스트 케이스만으로 언어 품질 판단 역량을 확인할 수 없다.
- 부족한 근거: 스프레드시트의 번역 검토만 했다면 빌드 내 LQA 실행과 구분한다. 언어의 개인적 선호·공식 기준·실제 오류가 섞인 보고는 판단 근거가 부족하다.
- 보완 행동: 허용된 빌드나 개인 샘플에서 대표 결함을 골라 환경·위치·재현·기대 기준·영향을 작성한다. 수정 권한이 없으면 권고와 실제 수정 결과를 구분한다.
- 보완 행동: 해당 공고의 플랫폼·로케일에 필요한 검수 범위만 정한다. 공고에 없는 모든 언어·기기·문화권 검증이나 기능 자동화를 필수로 요구하지 않는다.
- 완료 기준: 다른 검토자가 허용된 정보로 같은 위치·문제를 찾고, 오류 판단의 기준과 영향의 이유를 이해할 수 있다. 실제 확인한 조건과 미검증 범위가 표시된다.
- 완료 기준: 수정 확인을 주장하면 버전·재검수 결과·관련 회귀 범위가 연결된다. 공개 빌드의 개인 관찰은 실제 회사의 결함 처리·납품 이력으로 바꾸지 않는다.
- 면접 질문: “이 건을 언어 오류로 판단한 근거는 무엇인가요?”, “번역 문제처럼 보이지만 구현 문제였던 경우를 어떻게 구분하나요?”
- 면접 질문: “문자열 수정 후 어떤 화면을 다시 확인하나요?”, “같은 표현의 허용 가능한 변형과 일관성 오류를 어떻게 나누나요?”

## 역할을 섞지 않는 피드백

- 번역·감수 자료에는 의미·표현 선택과 수정의 근거를, PM 자료에는 범위·변경·협업의 근거를, LQA 자료에는 재현·판단·확인의 근거를 우선한다.
- 한 사람이 여러 역할을 했다면 역할별 담당 기간·권한·산출물을 분리하고, 동일 사례의 강점을 중복된 실적으로 부풀리지 않는다.
- 부족한 것은 설명·원문 맥락·실행 증거·확인 결과 중 무엇인지 특정한다. 번역을 더 많이 하라는 권고로 모든 보완을 대신하지 않는다.
- 새 과제의 분량·검수 범위는 확인하려는 주장에 필요한 수준으로 정한다. 위 완료 기준은 코칭의 작업 종료 기준이지 회사의 합격 보장이 아니다.
- 수정본은 해당 문장·일정 변경 기록·결함 보고의 새 근거를 확인해 재평가한다. 표나 파일 수가 늘었다는 이유만으로 역량이 향상됐다고 판단하지 않는다.
