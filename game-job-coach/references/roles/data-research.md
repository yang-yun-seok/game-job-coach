# 데이터·분석·리서치 직무

이 문서는 코칭용 관찰 기준이다. 해당 공고의 업무·필수·우대와 경력 수준을 먼저 읽고 관련 부분만 적용한다.
공통 근거 해석은 [직무별 기준](../role-criteria.md), 충족 상태는 [서류 진단](../document-review.md)을 따른다.
도구 이름만으로 역할을 정하지 않는다. 의사결정용 분석, 예측/모델링, 데이터 공급, 이용자 연구의 목적·산출물·책임을 구분한다.
분석 대상이 게임 이용자·사업 지표인지 전사 업무데이터인지 먼저 확인한다. 모델링·거버넌스 업무가 명시되면 용어·지표·데이터 소유 및 접근 책임을 정의하고 관계 부서와 조율한 근거를 확인한다.
공개·합성·가상 데이터와 대학 수업·개인 프로젝트도 설계·검증 근거가 된다. 상용 서비스 접근·실제 매출 개선·운영 배포 경험으로 바꾸지 않는다.
경력은 문제 정의·개발·검증·배포·운영·의사결정 중 맡은 단계와 영향 범위를 공고에 맞춰 평가한다.

## 게임 데이터·BI 분석

관찰할 핵심은 게임/사업 질문을 분석 가능한 정의로 바꾸고, 데이터의 한계를 포함해 의사결정에 연결하는 과정이다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 분석 질문·지표 사전 | 의사결정, 이벤트, 분자/분모, 기간, 집단, 제외 조건이 연결됨 | KPI 이름만 있고 중복 이용자·기간·복귀 등의 처리 정의가 없음 |
| 추출·집계·검증 쿼리 | 조인 단위·중복·결측·시간대 확인과 재현 가능한 입력/출력이 있음 | SQL 길이나 도구 사용만 제시하고 집계 정확성을 확인하지 않음 |
| 퍼널·코호트·세그먼트 | 집단 선정과 관찰 창을 설명하고 구성 변화·누락을 검토함 | 서로 다른 이용 기간·집단을 그대로 비교함 |
| 대시보드·시각화 | 사용자의 질문, 비교 기준, 갱신 시점, 해석상의 주의가 드러남 | 차트가 많지만 어떤 결정을 돕는지 불명확함 |
| 제안·실험 분석·후속 확인 | 관찰, 가설, 대안 원인, 권고와 실행 여부가 구분됨 | 상관관계를 원인으로 단정하거나 제안된 효과를 실적으로 씀 |

개선 완료 기준:

- 대표 지표를 정의→추출→검증→해석까지 따라갈 수 있고, 원자료가 없으면 공개 가능한 구조·집계로 한계를 설명한다.
- 대표 결론 하나의 근거와 반대 설명을 제시하고, 제안·적용·관찰 결과를 분리했다.
- 공개/가상 데이터 분석은 생성·수집 조건과 게임 이용자 전체로 일반화할 수 없는 부분을 적었다.

면접 질문:

- “같은 리텐션 지표가 팀마다 다르게 나왔을 때 어떤 정의와 쿼리 조건부터 비교하겠나요?”
- “분석 결과가 권고를 지지하지 않았던 사례에서 결론과 다음 행동을 어떻게 바꿨나요?”

## 데이터 사이언스·ML

관찰할 핵심은 모델 복잡도보다 문제에 맞는 목표·기준선·평가 설계·오류 해석과 적용 제약이다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 문제·타깃·의사결정 정의 | 예측 시점, 사용할 정보, 결과가 바꿀 행동과 오류 비용을 밝힘 | 모델 이름은 있으나 무엇을 언제 예측하는지 불명확함 |
| 데이터·특성·분할 설계 | 시간·이용자/집단 기준 분리, 중복·누수·편향 확인을 설명함 | 미래 정보나 같은 이용자 기록이 평가에 섞이는지 확인하지 않음 |
| 기준선·모델 비교 | 단순 기준선과 동일 조건 비교, 지표 선택·재현 설정이 있음 | 가장 높은 점수만 있고 비교 조건·선택 과정이 없음 |
| 오류·성능·불확실성 분석 | 클래스/집단별 실패, 비용·임계값, 관찰 범위와 한계를 제시함 | 정확도 하나로 불균형 문제나 실제 효용을 확정함 |
| 적용·모니터링·후속 검증 | 추론 비용·지연·데이터 변화·재평가를 공고상 역할 범위에서 설명함 | 오프라인 성능을 라이브 매출·이탈 감소 효과로 바꿈 |

개선 완료 기준:

- 예측 대상·시점·데이터 출처·분할·기준선·평가 지표·재현 조건을 일관되게 확인할 수 있다.
- 대표 실패 유형과 데이터 누수 확인, 실제 사용할 경우의 오류 비용을 설명했다.
- 학습 실험, 프로토타입, 배포, 실제 운영 효과를 구분하고 수행하지 않은 단계를 완료 경험처럼 쓰지 않았다.

면접 질문:

- “이 예측 시점에는 아직 알 수 없는 정보가 학습 데이터에 들어갈 가능성은 없나요?”
- “오프라인 점수는 좋아졌지만 실제 이용자 경험이 나빠질 수 있는 상황은 무엇인가요?”

## 데이터 엔지니어

관찰할 핵심은 데이터를 목적에 맞게 안정적으로 수집·변환·제공하고 품질·복구·비용을 설명하는 과정이다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 수집·모델·파이프라인 설계 | 생산자/소비자, 스키마, 처리 단위, 갱신 요구와 선택 이유가 있음 | 아키텍처 그림에 제품 로고만 있고 흐름·계약이 없음 |
| 변환·적재·스케줄 코드 | 입력/출력 정의와 의존성, 재시도·중복·순서·지연 처리를 설명함 | 정상 경로만 실행되며 재실행 시 결과가 달라지는지 모름 |
| 품질·관측·장애 대응 | 누락·중복·신선도 확인, 감지·원인·복구·검증 범위를 보여줌 | 로그를 쌓았다는 사실만으로 모니터링·복구 경험을 주장함 |
| 스키마 변경·백필 | 영향 대상·호환성·재처리 범위·결과 대조·중단/복원 계획이 있음 | 변경 후 실행 성공만 있고 다운스트림 영향 확인이 없음 |
| 성능·비용·운영 책임 | 처리량·지연·자원·비용의 측정 환경과 본인 담당을 밝힘 | 소규모 로컬 속도를 대규모 운영 성능으로 일반화함 |

개선 완료 기준:

- 대표 데이터 흐름의 입력→변환→제공과 담당 경계를 읽을 수 있고, 선택한 구조의 이유가 있다.
- 실제 또는 명시된 학습 실험에서 중복·누락·지연·실패 중 관련 사례의 재실행/복구 결과를 확인했다.
- 성능 수치는 데이터량·환경·반복 조건·비용 범위를 포함하고, 운영 경험과 실험 환경을 분리했다.

면접 질문:

- “같은 데이터를 재처리했을 때 중복이나 집계 변화가 생기지 않는지 어떻게 확인했나요?”
- “스키마 변경이 대시보드나 모델에 주는 영향을 어떻게 찾고 전달했나요?”

## UX·유저 리서치

관찰할 핵심은 연구 질문에 맞는 방법·대상·과제를 고르고, 관찰과 해석을 구분해 제품 판단에 연결하는 과정이다.
UX 화면 설계가 주업무이면 [기획의 UX 기준](design.md), 시각 제작도 맡는다면 [아트의 UI 기준](art.md)을 함께 읽는다. 리서치 직무에 시각 디자인 숙련을 일괄 요구하지 않는다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 연구 질문·계획 | 결정할 문제, 방법 선택, 대상, 과제, 제약과 표본의 한계를 설명함 | 인터뷰·설문을 했다는 사실만 있고 질문 목적이 없음 |
| 모집·동의·스크립트 | 대상 기준·모집 경로·안내·비식별 처리와 유도 질문 점검이 있음 | 지인 표본을 전체 이용자 대표로 보거나 불필요한 개인정보를 수집함 |
| 관찰 기록·분석 | 실제 발화/행동, 연구자 해석, 예외 사례와 분류 근거를 구분함 | 인상적인 발언만 선택하거나 관찰하지 않은 동기를 확정함 |
| 설문·사용성 결과 | 문항·응답 기준·분모·과제 조건·중도 포기와 편향을 밝힘 | 소표본 비율을 모집단의 정확한 선호·성공률로 일반화함 |
| 인사이트·제안·후속 평가 | 발견의 근거·영향·대안·반영 여부·재검증 범위를 연결함 | 페르소나나 보고서가 있다는 사실만으로 제품 개선을 주장함 |

개선 완료 기준:

- 대표 발견 하나를 연구 질문→대상/과제→익명 관찰→해석→제안으로 추적할 수 있다.
- 참여자 수·모집 경로·조건과 상반된 관찰, 편향·해석 한계를 명시했다.
- 실제 참여 연구, 공개 후기 분석, 가상 페르소나·인터뷰 연습을 구분하고 가상 발화를 실제 이용자 의견으로 쓰지 않았다.

면접 질문:

- “가장 강한 결론을 지지하지 않는 참여자의 행동이나 발언은 무엇이었나요?”
- “지인 몇 명의 관찰로 말할 수 있는 것과 추가 검증이 필요한 것을 나눠 주세요.”

## 수치·추론·자료 취급의 공통 기준

- 성과마다 지표 정의, 분자/분모 또는 집계 단위, 집단, 기간, 기준선, 비용·투입, 출처, 본인 기여와 적용 여부를 확인한다.
- 매출·처리 비용 등 절대액은 통화·총액/순액·비용 포함 범위를 밝힌다. 예측값·합성값·관찰값과 매출/광고 집행 실적을 섞지 않는다.
- 표본 수만으로 연구 품질을 단정하지 않는다. 질문·방법·자료 특성·편향과 허용되는 해석의 범위를 평가한다.
- 단순 전후 비교·상관관계·예측 성능·인과 추론은 서로 다르다. 무작위 배정 또는 식별 가정 등 근거 없이 인과 효과를 확정하지 않는다.
- 실험을 평가할 때 배정 단위, 기간, 지표, 집단 간 차이, 중도 중단·다중 비교 등 해당 설계에 관련된 한계를 확인한다.
- 신뢰구간·유의성·효과 크기는 방법과 가정이 확인되는 범위에서 해석한다. 통계 검정 하나로 사업적 가치나 결론의 진실을 보증하지 않는다.
- 예측 매출·이탈·LTV 등은 모델·기간·비용·가정이 있는 추정이다. 실제 사업 성과와 구분하고 수익 전망을 확정적으로 말하지 않는다.
- 고객 원본 로그·계정·연구 참여자 신원·인터뷰 녹취·내부 데이터·계약의 기밀 반출을 요구하지 않는다. 익명 집계·공개 데이터·합성 예제로 대체한다.
- 익명화는 재식별 위험이 남을 수 있음을 고려해 공개 가능한 범위를 따른다. 데이터 활용의 법적 적정성을 코칭만으로 단정하지 않는다.
- 대체 자료는 원본을 검증한 것처럼 평가하지 않는다. 데이터가 공개 불가하면 문제·구조·판단·한계를 설명한 범위의 근거로 인정한다.
- 경력 평가에는 분석 제안과 채택, 모델 개발과 배포, 파이프라인 구축과 운영, 연구 수행과 제품 결정의 책임 경계를 적는다.
- 공고가 요구하지 않은 상용 규모·특정 도구·고급 통계·배포·A/B 실험 경험을 모든 지원자의 필수 조건으로 만들지 않는다.
