# 제작·사업·퍼블리싱 직무

이 문서는 코칭용 관찰 기준이다. 회사 공고의 업무·필수·우대와 지원자의 경력 수준이 우선이며, 아래 산출물 목록을 새 필수 제출물로 만들지 않는다.
공통 근거 해석은 [직무별 기준](../role-criteria.md), 서류의 충족 상태는 [서류 진단](../document-review.md)을 따른다.

## 직무를 나누는 기준

| 공고에서 확인한 업무 | 우선 읽을 부분 | 먼저 확인할 경계 |
|---|---|---|
| 일정·범위·제작 의존성·개발팀 조율 | 개발 PM·프로듀서 | 일정 지원, 제작 의사결정, 조직·예산 책임 중 실제 범위 |
| 이용자·시장·상품·지표·출시 후 성장 | 사업·프로덕트 PM | 제품 우선순위, BM 기획, 사업 운영, 분석 지원 중 실제 범위 |
| 외부 개발사·플랫폼·IP·지역 파트너 협업 | 퍼블리싱·BD·파트너 관리 | 신규 발굴·협상·계약 이후 실행·운영 관리의 담당 범위 |

`PM`, `PD`, `사업`, `프로듀서`라는 제목만으로 세부 역할을 확정하지 않는다. 공고의 동사·산출물·협업 대상·결정 권한을 함께 읽는다.
한 사람이 여러 역할을 맡았다면 경험 단위로 분리해 평가하고, 회사마다 직무 명칭이 다른 점을 표시한다.
Technical·빌드 PM은 일정·검수 조율과 빌드 환경 구성·배포·자동화의 실제 책임을 구분한다. 직접 기술 작업을 맡는 공고에는 [개발의 툴·빌드 기준](engineering.md)을 함께 적용한다.
신입의 팀 프로젝트·동아리·공모전·수업 과제도 계획·조정·판단의 근거로 인정하되 상용 출시·매출 경험으로 바꾸지 않는다.
경력은 직급이나 프로젝트 규모 자체보다 맡은 단계·팀 범위·승인 권한·예산 관여·실행 결과를 공고와 대조한다.

## 개발 PM·프로듀서

관찰할 핵심은 제작 목표를 범위·일정·의존성으로 바꾸고, 변화를 발견해 결정과 실행으로 연결한 과정이다.
프로듀서 공고에 제품 방향·인력·예산 책임이 명시되면 그 범위를 추가로 확인한다. 모든 개발 PM에게 최종 제작 권한을 요구하지 않는다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 마일스톤·작업 분해·완료 정의 | 목표, 선후 관계, 담당, 수용 조건이 연결되고 변경 이유를 설명함 | 일정표의 색과 날짜만 있거나 실제 완료 기준이 없음 |
| 의존성·리스크 기록 | 선행 작업 지연의 영향과 선택 가능한 대응, 판단 시점이 남음 | 위험 목록만 있고 담당·트리거·후속 확인이 없음 |
| 변경·우선순위 결정 기록 | 변경 요청의 가치·비용·품질 영향을 비교하고 합의 범위를 설명함 | 요청을 모두 수용한 것을 조율 성과로만 제시함 |
| 회의·협업·전달 산출물 | 쟁점, 결정권자, 결정, 실행 담당, 후속 확인이 이어짐 | 회의 횟수·문서 수·사용 도구만으로 협업 품질을 주장함 |
| 빌드·검수·출시 준비 | 단계별 통과 조건과 미해결 이슈, 다른 직군의 확인 범위가 드러남 | 출시 성공을 주장하지만 본인 담당 단계나 검수 범위가 없음 |
| 일정·품질 회고 | 계획 대비 차이, 원인, 본인 조치와 다음 반복에서 확인한 변화를 제시함 | ‘일정 준수 100%’만 있고 범위 축소·추가 투입·기준 변경이 빠짐 |

개선 완료 기준:

- 대표 마일스톤 하나에 목표·담당·의존성·완료 조건을 연결해 다른 사람이 진행 상태를 읽을 수 있다.
- 실제 변경 사례 하나에서 원안, 새 제약, 선택지, 결정 주체, 본인 행동, 결과를 구분했다.
- 일정 수치에는 최초 계획·변경된 범위·측정 구간·투입 변화가 붙고, 본인 통제 밖의 결과는 따로 적었다.
- 학습 프로젝트라면 실행한 조정과 제안만 한 운영안을 분리하고, 실패·미완료 구간도 설명했다.

면접 질문:

- “선행 작업이 늦어졌을 때 무엇을 줄이거나 미뤘으며, 그 결정 권한은 누구에게 있었나요?”
- “일정은 맞췄지만 품질 또는 작업 범위가 달라진 사례를 어떻게 보고했나요?”
- “여러 직군의 의견이 충돌한 한 건에서 본인이 결정한 일과 결정을 도운 일을 나눠 주세요.”
- “경력 기술서의 제작 성과 중 본인이 책임졌던 단계와 다른 책임자의 역할은 무엇인가요?”

## 사업·프로덕트 PM

관찰할 핵심은 이용자·제품·사업 문제를 정의하고, 대안을 고른 이유와 실행 후 판단을 설명하는 능력이다.
사업 PM과 프로덕트 PM의 경계는 공고에 따른다. 매출 관리, 기능 우선순위, 운영 조율을 한 직무의 고정 필수 조건으로 묶지 않는다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 문제 정의·시장/이용자 분석 | 대상·상황·자료 출처·가설과 관찰을 구분하고 제품 결정에 연결함 | 시장 규모나 경쟁사 소개는 많지만 해결하려는 문제가 불명확함 |
| 제품 요구·로드맵·우선순위 | 목표, 수용 조건, 대안, 의존성, 보류 이유가 드러남 | 기능 목록을 로드맵이라고 부르거나 점수만 있고 입력 근거가 없음 |
| 상품·BM·프로모션 제안 | 대상 이용자·가치·가격 가정·노출/구매 흐름·운영 제약을 설명함 | 다른 게임 가격을 복사하거나 수익 상승을 근거 없이 확정함 |
| 지표 정의·퍼널·코호트 | 이벤트, 분모, 기간, 집단과 분석 한계를 밝히고 판단에 연결함 | DAU·매출 증감만 나열하고 유입 구성·패치·시즌 영향을 생략함 |
| 실험·출시 후 검토 | 사전 가설·판정 조건·관찰 결과·다음 결정을 연결함 | 전후 상승을 모두 변경 효과로 보거나 검증 계획을 실험 결과로 제시함 |
| 손익·예산 검토 | 가정, 비용 포함 범위, 시나리오, 민감도와 결정 용도를 밝힘 | 예상 매출을 확정 성과로 쓰거나 비용을 제외한 수치로 수익성을 단정함 |

개선 완료 기준:

- 대표 제품 결정 하나가 `문제 → 근거 → 대안 → 선택 → 실행 범위 → 관찰 → 다음 판단`으로 이어진다.
- 매출·리텐션 등의 수치마다 정의·대상·기간·비교군 또는 기준선·비용·본인 기여가 확인된다.
- 직접 실행하지 않은 제안은 가정과 검증 계획으로 표기하고, 실제 운영 결과와 분리했다.
- 공개 자료로 만든 분석은 출처 시점과 알 수 없는 내부 수치를 밝히며, 수익 예측에는 가정별 범위가 있다.

면접 질문:

- “같은 문제를 풀 수 있는 다른 대안을 왜 보류했고, 어떤 증거가 나오면 결정을 바꾸겠나요?”
- “지표가 좋아졌다는 해석을 뒤집을 수 있는 유입·시즌·비용 변화는 무엇인가요?”
- “제품 우선순위나 예산에 대해 제안·승인·집행 중 어느 단계까지 담당했나요?”
- “모의 분석에서 실제 이용자 데이터가 확보된다면 가장 먼저 검증할 가정은 무엇인가요?”

## 퍼블리싱·BD·파트너 관리

관찰할 핵심은 외부 협업의 목적과 상대 조건을 이해하고, 내부 실행·합의·후속 관리를 연결하는 과정이다.
신규 사업 발굴, 출시 지원, 플랫폼 대응, 지역 운영, 파트너 유지 업무를 구분하며 모두 수행했다고 가정하지 않는다.

| 산출물·관찰 증거 | 좋은 근거 | 부족하거나 확인이 필요한 근거 |
|---|---|---|
| 파트너·프로젝트 검토 메모 | 선정 목적·정보 출처·비교 기준·불확실성·추가 확인 항목이 연결됨 | 유명 회사 목록이나 개인 선호를 사업 적합성의 증거로 사용함 |
| 제안·협의 자료 | 각 당사자의 목표·제약·교환 가능한 조건·미합의 사항을 구분함 | 미팅 참석·메일 발송 수만으로 협상 또는 계약 성과를 주장함 |
| 출시·이관·지역화 체크 | 제출·검수·권한·일정의 담당과 의존성, 승인 상태를 설명함 | 출시 자체는 있으나 본인 관여와 파트너/개발팀 책임이 없음 |
| 파트너 이슈·액션 추적 | 사실 확인, 내부 전달, 결정, 약속한 기한, 종결 기준이 이어짐 | ‘관계 유지’만 쓰고 어떤 문제를 해결했는지 확인할 수 없음 |
| 사업 조건·리스크 검토 | 비용·수익 배분 가정·권리 범위·승인 필요 쟁점을 분리함 | 계약 금액을 개인 실적으로 귀속하거나 법률상 유효성을 단정함 |
| 협업 결과·회고 | 목표 대비 결과와 본인의 발굴·조율·운영 기여, 남은 과제를 밝힘 | 체결·출시·갱신을 같은 성과로 묶거나 팀 성과를 전부 본인에게 귀속함 |

개선 완료 기준:

- 대표 협업 한 건에 협업 목적·상대/내부 역할·합의 사항·본인 담당·결과를 익명 사례로 정리했다.
- 협상 제안, 최종 승인, 계약 체결, 실제 이행을 나눠 각 단계의 근거와 권한을 밝혔다.
- 시장·수익·계약 관련 판단에는 출처·가정·확인 주체가 있으며 예상과 실적을 분리했다.
- 신입의 모의 제안서는 실제 접촉·계약 실적처럼 쓰지 않고 비교 기준과 협업 실행 계획으로 평가한다.

면접 질문:

- “양측 목표가 충돌한 사례에서 양보 가능한 조건과 확인이 필요한 조건을 어떻게 구분했나요?”
- “계약 이후 약속이 지연됐을 때 어떤 사실을 확인하고 누구와 실행안을 정했나요?”
- “본인이 발굴·제안·협상 지원·승인·운영한 범위를 각각 구분해 주세요.”
- “공개 자료만으로 판단할 수 없는 항목은 무엇이며, 추가 확인 없이 어떤 결정을 피했나요?”

## 성과·기밀·책임 범위 점검

- 수치는 지표 정의, 분자/분모 또는 집계 단위, 집단, 기간, 기준선, 비용·투입, 자료 출처, 본인 기여를 함께 확인한다.
- 분모가 없는 절대 매출·비용은 통화·총액/순액·정산 범위·기간을 명시한다. 모든 지표에 임의의 분모를 만들지 않는다.
- 상관관계, 단순 전후 비교, 인과 추론을 구분한다. 통제되지 않은 변화는 기여 가능성으로 설명하고 효과를 확정하지 않는다.
- 수익 전망은 가정과 불확실성이 있는 시나리오다. 통계적 유의성이나 계약의 법률적 효력을 권위적으로 단정하지 않는다.
- 비공개 일정·예산·파트너 계약·대화·로그의 원본 반출을 요구하지 않는다. 공개 가능한 요약, 익명화 사례, 재구성 표로 대체할 수 있다.
- 익명화·재구성 자료는 변형 범위를 표시하고, 확인할 수 없는 항목은 미확인으로 둔다. 재구성을 실제 원본 검증으로 취급하지 않는다.
- 신입은 과제에서 드러난 판단과 학습을, 경력은 공고가 요구하는 책임과 실행 범위를 평가한다. 회사 규모나 실매출 증빙을 임의의 채용컷으로 만들지 않는다.
