# 아트 직무의 근거를 읽는 관점

회사 공고의 담당 업무·스타일·제작 단계·경력 수준이 우선이다. 아래는 코칭용 제안 기준이며 업계 공통 채용컷이나 회사의 평가표가 아니다.
공고가 없는 장르·실사/캐주얼 스타일·엔진·툴·폴리곤 수·텍스처 규격·포트폴리오 수량을 필수로 만들지 않는다. 보완 예시의 분량도 합격 기준이 아니다.
같은 캐릭터 영상이라도 원화는 조형 선택, 모델링은 입체 제작, 애니메이션은 동작, TA는 제작 문제 해결의 근거로 다르게 읽는다.
세부 직무가 섞인 공고는 요구된 책임을 나누고, 하나의 완성 화면으로 모든 직무 역량을 확인했다고 하지 않는다.

## 공통 확인과 관찰 한계

- `자료 위치 → 직접 본 결과 → 본인 선택·기여 → 설명 가능한 역량 → 한계·보완`으로 판단을 연결한다.
- 원본 레퍼런스, 기존 게임 화면, 본인 시안, 공동 작업, 구매/배포 에셋, 생성 도구 사용 부분을 구분한다. 레퍼런스의 품질을 본인 결과물의 품질로 평가하지 않는다.
- 이미지·영상·실행 화면을 직접 확인하지 못하면 시각 품질과 동작 평가는 유보한다. 텍스트 설명으로 작업 의도·과정만 검토할 수 있다.
- 해상도·압축·촬영 조건으로 확인되지 않는 디테일은 결함으로 단정하지 않는다. 정지 화면으로 움직임·성능·플레이 중 가독성을 확정하지 않는다.
- 신입의 개인 작품·모작·리디자인·학습 프로젝트도 선택·수정의 근거가 된다. 출시·납품·실사용 성과, 원작의 제작 기여로 바꾸지 않는다.
- 기밀 소스·미공개 에셋·권리 없는 원본 공개를 요구하지 않는다. 허용된 캡처·익명화한 과정 설명·별도 개인 샘플로 확인 범위를 조정한다.
- 작업 시간이 짧다는 사실만으로 생산성을, 아름다운 최종 이미지 하나만으로 협업·게임 적용 역량을 입증하지 않는다.

## 컨셉·원화

- 담당 결과물: 캐릭터·배경·소품의 시각적 방향, 형태·색·소재 탐색, 제작 의도를 전달하는 원화. 공고에 따라 일러스트 완성과 제작용 설정을 구분한다.
- 관찰 증거: 과제 의도, 레퍼런스 출처, 썸네일·변형 시안, 선택 이유, 최종안과 필요한 구조·재질 설명, 피드백에 따른 수정.
- 좋은 근거: 세계관·플레이 역할·시점이라는 제약을 형태와 색 선택에 연결하고, 버린 대안과 수정 이유가 실제 시안에 보인다.
- 부족한 근거: 완성 그림만으로는 탐색·설계 전달을 확인하기 어렵다. 모작의 충실도는 관찰 가능하지만 독자적인 컨셉 결정의 증거와는 구분한다.
- 보완 행동: 대표 작품의 목표와 본인 범위를 밝히고, 실제 보유한 시안에 선택 근거를 붙인다. 과거 시안이 없으면 새 탐색 과제로 명시한다.
- 완료 기준: 선택 전후 차이와 이유를 그림 위치로 짚을 수 있고, 다음 제작자가 알아야 할 형태·소재·미확정 사항이 구분된다. 불필요한 설정도 수량을 채우게 하지 않는다.
- 면접 질문: “어떤 제약 때문에 이 실루엣을 골랐나요?”, “제작자가 해석을 달리했던 부분을 어떻게 정리했나요?”

## 3D 캐릭터

- 담당 결과물: 캐릭터 모델·표면·머티리얼과 해당 공고가 요구하는 게임 적용 자산. 모델링과 리깅·애니메이션 책임을 임의로 합치지 않는다.
- 관찰 증거: 여러 각도의 모델, 목표 디자인 대비 변형, 본인 제작 범위, 필요 시 토폴로지·UV·베이크·재질·엔진 적용과 규격.
- 좋은 근거: 외형 선택과 제작 제약을 설명하고, 베이크 오류·이음새·변형 문제 같은 실제 문제의 수정 전후를 확인할 수 있다.
- 부족한 근거: 한 장의 렌더로 가려진 면·토폴로지·변형·런타임 비용을 확정할 수 없다. 스캔·베이스 메시·외부 텍스처의 기여도 분리가 필요하다.
- 보완 행동: 대표 자산에 본인이 만든 단계와 확인할 수 있는 뷰를 붙이고, 공고가 게임 적용을 요구하면 실제 적용 결과와 발견 문제를 보충한다.
- 완료 기준: 목표 외형과 결과를 같은 부분에서 비교할 수 있고, 요구된 제작 단계의 결과·제약·잔여 문제가 확인된다. 예산 수치는 공고 또는 프로젝트의 실제 기준을 쓴다.
- 면접 질문: “외형을 유지하면서 어떤 부분의 제작 비용을 줄였나요?”, “베이크나 변형 문제의 원인을 어떻게 좁혔나요?”

## 배경·환경

- 담당 결과물: 배경 에셋·모듈·재질·장면 구성 등 맡은 범위의 환경. 레벨의 플레이 규칙 설계와 환경의 시각 제작 책임을 구분한다.
- 관찰 증거: 담당 에셋과 외부 에셋 구분, 장면 의도, 스케일·모듈 규칙, 배치·재질·조명 변화, 필요 시 실제 카메라와 성능 조건.
- 좋은 근거: 반복 제작·접합·시선 유도 등 실제 문제를 자산 또는 배치 선택으로 해결하고, 수정 전후 장면에서 차이가 보인다.
- 부족한 근거: 구매 에셋을 활용한 장면도 구성 근거가 되지만 모든 모델의 제작 실력을 입증하지 않는다. 스크린샷만으로 이동 중 가독성·최적화를 확정하지 않는다.
- 보완 행동: 대표 구간에 직접 제작·조합·조명 담당을 표시하고, 공고와 관련 있는 모듈 접합 또는 플레이 시점 문제 하나의 해결 과정을 정리한다.
- 완료 기준: 기여 범위를 장면과 에셋에 대응할 수 있고, 선택한 문제의 발생 조건·수정·확인 결과가 연결된다. 성능 개선을 주장하면 측정 환경과 비교 조건을 함께 제시한다.
- 면접 질문: “반복 구조가 눈에 띄는 문제를 어떻게 줄였나요?”, “플레이 시야와 장면 연출이 충돌했을 때 무엇을 조정했나요?”

## 애니메이션·리깅

- 담당 결과물: 애니메이션은 포즈·타이밍·이동·전환의 표현, 리깅은 조작·변형을 지원하는 구조와 도구. 결합 공고가 아니면 서로의 결과를 일괄 요구하지 않는다.
- 관찰 증거: 애니메이션은 실제 재생 영상·키 포즈·수정 비교, 리깅은 컨트롤 사용·극단 포즈·변형 테스트와 제작자가 겪은 문제.
- 좋은 근거: 의도한 무게감·행동 판독을 동작 선택에 연결하거나, 조작·변형 문제를 재현하고 리그 변경 효과를 보여준다.
- 부족한 근거: 스틸컷은 타이밍을, 리그 컨트롤 개수는 사용성을 입증하지 않는다. 모션캡처 원본과 본인 클린업·키프레임·리타깃 작업을 구분한다.
- 보완 행동: 해당 책임에 맞는 동작 또는 변형 문제를 골라 원본·본인 수정·실제 재생 결과를 붙인다. 런타임 전환은 공고에 필요할 때 추가한다.
- 완료 기준: 동일 동작·포즈 조건의 전후 차이를 재생하거나 확인할 수 있고, 수정 의도와 남은 제약을 설명할 수 있다. 리깅과 애니메이션의 기여자가 표시된다.
- 면접 질문: “이 동작을 읽게 만드는 핵심 포즈는 무엇인가요?”, “리그 사용자의 반복 문제를 어떤 테스트로 확인했나요?”

## VFX

- 담당 결과물: 스킬·피격·환경 등 게임 상황의 효과와 필요한 제작 자산·설정. 영상 합성과 실제 게임 효과 적용은 작업 성격을 구분한다.
- 관찰 증거: 효과의 예고·발생·잔상, 게임 시점 영상, 원본 자산과 본인 제작 부분, 필요 시 머티리얼·파티클 구성·비용 측정과 수정.
- 좋은 근거: 타격·위험·범위 전달 목표를 시간·형태·색 선택에 연결하고, 복잡한 화면에서의 판독 또는 비용 문제를 실제 조건으로 확인한다.
- 부족한 근거: 검은 배경의 단독 효과만으로 전투 중 가독성·성능을 판단하기 어렵다. 입자 수가 많거나 화려하다는 사실 자체를 좋은 품질로 보지 않는다.
- 보완 행동: 대표 효과의 전달 목표와 본인 자산을 밝히고, 목표와 관련된 배경·시점·동시 발생 조건에서 결과를 확인한다.
- 완료 기준: 전달해야 하는 순간과 관찰한 결과가 대응하며, 문제를 고쳤다면 전후 영상 또는 측정이 같은 조건으로 연결된다. 미측정 성능은 미확인으로 남긴다.
- 면접 질문: “효과를 줄여도 반드시 남겨야 할 정보는 무엇인가요?”, “겹치는 효과 속 판독 문제를 어떻게 확인했나요?”

## 테크니컬 아트(TA)

- TA는 공고에 따라 시뮬레이션·아트 제작 지원, 도구·파이프라인, 모바일 리소스 규격·성능 예산 등 중심 업무가 달라진다. 실제 담당 산출물에 해당하는 근거를 선택한다.
- 담당 결과물: 공고가 정한 셰이더·제작 도구·파이프라인·최적화·기술 지원. TA라는 직함만으로 모든 영역의 전문성을 요구하지 않는다.
- 관찰 증거: 제작자의 문제·입출력·제약, 본인 구현 범위, 사용 화면·코드 또는 공개 가능한 구조 설명, 적용 결과와 실패·예외 처리.
- 좋은 근거: 제작 병목을 재현하고 도구·셰이더·규칙의 선택 이유를 설명하며, 수정 효과를 사용 사례 또는 같은 조건의 측정으로 보여준다.
- 부족한 근거: 멋진 셰이더 영상만으로 제작 도구 설계·협업을, 코드 줄 수만으로 유지보수성과 생산성 향상을 확인할 수 없다.
- 보완 행동: 목표 업무와 가장 가까운 문제 하나의 이전 절차→본인 해결→확인 결과를 정리한다. 개인 도구라면 실제 팀 도입 성과로 표현하지 않는다.
- 완료 기준: 입력부터 결과까지 실행 또는 허용된 데모로 따라갈 수 있고, 실패 조건·사용자 범위·효과의 측정 여부가 표시된다. 민감한 코드 공개는 필요조건이 아니다.
- 면접 질문: “자동화하지 않은 단계는 왜 남겼나요?”, “다른 제작자가 잘못된 입력을 넣었을 때 어떻게 안내하나요?”

## UI·비주얼 디자인

- 담당 결과물: 화면의 시각 체계, 타이포그래피·아이콘·그래픽·컴포넌트 상태·모션 등 공고의 표현 책임. UX 설계·사용자 조사와 구분하되 결합 공고의 교차 업무는 확인한다.
- 관찰 증거: 실제 화면과 상태별 시각 변화, 스타일·정보 위계의 선택 이유, 자산·컴포넌트 규칙, 필요 시 해상도·문자 길이·엔진 전달 및 적용.
- 좋은 근거: 핵심 정보·브랜드 의도를 실제 화면에 일관되게 적용하고, 상태나 제약 변화에서도 판독·표현 규칙이 유지되는지 확인한다.
- 부족한 근거: 아름다운 단일 화면은 전체 플로우·사용성 검증을 입증하지 않는다. UX 리서치가 없다고 시각 제작 역량을 미충족 처리하지 않으며, 리서치 보고서를 그래픽 완성도로 평가하지 않는다.
- 보완 행동: 대표 화면에서 핵심 컴포넌트와 실제로 필요한 상태·문자 길이 변화의 결과를 묶고, 리디자인은 원본·문제 가설·본인 결과를 구분한다.
- 완료 기준: 시각 선택을 화면 위치로 설명할 수 있고, 선택한 상태·규격의 결과와 전달 항목이 확인된다. 실제 사용자 검증이 없으면 사용성 향상은 가설로 표시한다.
- 면접 질문: “어떤 정보가 먼저 보이도록 설계했나요?”, “기획·개발 요구로 표현 규칙을 바꾼 사례와 유지한 기준은 무엇인가요?”
