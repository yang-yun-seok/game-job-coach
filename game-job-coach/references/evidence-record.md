# 공고·경험 근거와 작업 기록

같은 지원 건의 후속 작업이나 사용자가 요청한 경험 정리에 사용한다. 작업에 필요한 항목만 기록하며 모든 모드에서 별도 파일 작성을 강제하지 않는다.

반복 사용을 위한 파일을 만들 때는 [취업 준비 기록 양식](../assets/career-record-template.md)을 필요한 부분만 복사하여 작업 폴더에서 사용한다. 양식은 빈 구조이며 지원자의 실제 경험이나 선호가 아니다. 이미 기록 파일이 있으면 그 형식을 우선하고 중복 파일을 만들지 않는다.

## 지원자와 지원 건 구분

지원자 공통 기록에는 목표 직무·세부 분야, 확인된 경력, 실제로 말한 선호와 제약, 공통 경험·자료 목록을 둔다. 회사별 기록에는 공고 버전·마감·문항·제출본·준비 상태를 둔다. 사용자에게 이미 제공한 정보를 다시 입력하게 하지 않는다.

경험 ID는 공통 목록 안에서 유지하고, 요건·지적 ID는 지원 건 안에서 유지한다. 서로 다른 회사의 M01·I01은 같은 항목이 아니다. 경험을 고칠 때 관련 지원 서류도 확인하되 이미 제출한 파일을 자동으로 덮어쓰지 않는다.

## 공고 요건

| 필드 | 기록할 내용 |
|---|---|
| 지원 건 | 회사·프로젝트·직무, 같은 회사의 다른 공고를 구분할 정보 |
| 출처·버전 | 공고 URL 또는 제공 파일, 확인일, 게시·수정일은 확인된 경우만 |
| 요건 ID | 담당 업무 W01, 필수 M01, 우대 P01 등 원래 항목 순서와 연결 |
| 명시 내용 | 요건을 식별하는 요약과 위치, 공고상 필수·우대 구분 |
| 해석 | 요구 역량, 해석 근거, 불확실성과 확인할 질문 |

새 공고가 기존 공고와 다른 버전이면 달라진 항목을 확인한다. 다른 공고의 ID와 판단을 그대로 이어 붙이지 않는다.

## 지원자 경험

| 필드 | 기록할 내용 |
|---|---|
| 경험 ID | E01 등 지원 건에서 일관되게 사용할 식별자 |
| 프로젝트 | 이름, 기간, 팀 규모, 작업의 성격: 실제 개발·운영·제안·역기획·학습 등 |
| 목적·문제 | 어떤 목표와 제약 속에서 해결할 문제가 있었는지 |
| 본인 기여 | 직접 수행·결정한 일과 협업 범위, 팀 전체 작업과의 구분 |
| 행동·판단 | 선택한 방법·대안·선택 근거, 사용한 도구 |
| 결과·학습 | 확인된 수치 또는 정성 결과, 측정 범위·본인 기여, 배운 점 |
| 근거 | 파일명·버전·페이지·섹션 또는 관련 대화, 진술인지 결과물 확인인지 |
| 확인 필요 | 미제공 사실, 자료 간 충돌, 아직 읽지 못한 범위 |

사용자 진술도 근거로 기록할 수 있다. 외부 증명이 없다는 이유로 실제 경험을 거부하지 않는다. 다만 진술을 독립적으로 검증한 사실로 격상하지 않는다.

## 연결 및 면접 기록

요건 ID ↔ 경험 ID ↔ 근거 위치 ↔ 문서상 충족 상태를 연결한다. 동일 경험을 자소서와 면접에 사용할 때 역할·기간·수치가 일관되는지 확인한다.

면접을 저장할 때는 목표 공고·자료 버전, 모드, 주요 질문 수, 질문과 답변 요지, 근거 경험 ID, 피드백, 재연습 전후의 변화와 남은 과제, 다음 질문 또는 연습 과제를 남긴다. 사용자가 답하지 않은 질문의 답변을 생성해 기록하지 않는다.

자소서 문항별 경험 배치와 [수정 전후 검토](revision-review.md)의 지적·상태·완료 기준도 같은 지원 건에 연결한다. 사용자가 재사용을 요청하면 최신 근거가 어느 파일인지 먼저 확인하고 미해결 지적에서 이어간다. 과거 기록의 요약과 새 자료가 다르면 실제 자료를 읽고 차이를 명시한다.

## 파일로 남길 때

사용자가 지정한 폴더·파일명이 있으면 따른다. 별도 지정이 없고 파일 산출물을 요청했다면 작업 폴더 안에서 회사·직무·문서 용도를 구분하는 이름을 쓴다. 원본과 제출본을 분석 메모로 덮어쓰지 않는다.

공통 스킬 폴더에는 개인 자료를 넣지 않는다. 주민번호·주소·연락처 등 이번 판단에 불필요한 개인정보를 분석 기록에 반복 복사하지 않는다. 이전 작업을 이어갈 때 파일을 실제로 다시 읽고, 남은 불확실성과 버전을 확인한다.
