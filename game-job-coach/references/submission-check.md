# 제출 직전 점검

‘지금 제출해도 되는지’, ‘최종 파일을 확인해 달라’는 요청에서 사용한다. 일반 첨삭마다 전체 점검을 강제하지 않는다. 실제 제출·업로드·공유 권한 변경은 점검과 별개이며 사용자의 요청 범위를 따른다.

## 실제 조건과 제출본 대조

- 같은 지원 건의 공고·접수 안내와 사용자가 제출하려는 파일·버전을 확인한다. 초안이나 최근 수정 파일을 임의로 최종본으로 선택하지 않는다.
- 명시된 필수 자료, 허용 형식·용량·제출 경로, 문항 제한, 기여 표기를 대조한다. 선택 자료는 필수로 만들지 않고 공고에 없는 용량·쪽수·영상 조건을 추가하지 않는다.
- 공고나 과제 안내에 AI 사용·외부 에셋·협업 기여에 관한 조건이 있으면 실제 사용 범위와 대조한다. 사용자의 작성 보조와 본인 설계·제작을 구분하고, 다른 회사의 규정을 가져오지 않는다. 알려지지 않은 사용 이력은 추정하지 않는다.
- 회사·직무·프로젝트명, 기간·역할·수치가 최종 자료 사이에서 일치하는지 확인한다. 교체가 필요한 위치를 짚고 맞는 내용을 일괄 재작성하지 않는다.

## 파일과 열람 확인

- 실제 파일이 있으면 열리는지, 명시 용량 제한과 확장자가 맞는지, 핵심 표·이미지·수정된 페이지가 잘리지 않고 읽히는지 가능한 수단으로 확인한다. 텍스트 추출만으로 레이아웃 점검을 완료하지 않는다. 일부 페이지만 봤으면 그 범위를 밝힌다.
- 글자 수는 실제 계산 도구와 확인된 입력 기준을 사용한다. 상세 기준은 [자소서 지침](cover-letter.md#글자-수와-예시)을 따른다.
- 링크는 허용된 제출 경로인지 먼저 보고 실제 접근 결과를 확인한다. 로그인된 본인 계정에서 열렸다는 사실을 외부 검토자의 열람 보장으로 바꾸지 않는다. 권한을 직접 바꾸거나 비공개 자료를 공개 상태로 만들지 않는다.
- 파일·영상·음원·링크를 확인할 수 없으면 해당 부분만 미확인으로 남긴다. 사용자가 ‘확인했다’고 말한 내용과 코치가 직접 확인한 내용을 구분한다. 필요한 확인 방법을 짧게 안내하고 읽을 수 있는 부분의 검토는 마친다.

## 결론과 남은 행동

관찰한 결과에 맞춰 아래 내용을 필요한 만큼 구분한다. 세 항목을 매번 채우거나 각각 별도 표로 만들 필요는 없다.

- **먼저 고칠 사항**: 금지된 경로, 필수 자료 누락, 잘못된 회사명, 사실·계산 오류 등 확인된 문제. 위치·근거·최소 수정과 완료 조건을 붙인다.
- **남은 확인**: PDF를 받지 못했거나 외부 접근을 확인하지 못한 범위. 미확인은 실제 결함이나 지원 자격 미충족이 아니다.
- **유지하거나 선택적으로 다듬을 사항**: 제출을 막지 않는 표현·배치 차이. 마감이 가깝다면 전체 재편집보다 필요한 수정과 최종 확인을 우선한다.

‘읽은 범위에서 제출 조건 충돌을 찾지 못했다’, ‘내용 검토는 끝났지만 최종 PDF는 미확인’처럼 관찰 범위에 맞춰 결론을 낸다. 검토 완료를 합격 가능성·직무 실력의 보장으로 표현하지 않는다. 모든 확인을 끝낼 때까지 지원 자체를 금지하는 식으로 말하지 않는다.
