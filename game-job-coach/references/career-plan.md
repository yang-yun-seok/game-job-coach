# 취업 준비와 지원 우선순위

‘게임업계 취업 준비를 도와줘’, ‘어디부터 고칠까’, ‘여러 공고 중 준비 순서를 정해줘’, ‘마감까지 할 일을 정해줘’ 같은 요청에서 사용한다. 구체적 공고 분석·서류 첨삭·면접 요청만 들어온 경우 전체 계획을 먼저 요구하지 않는다.

## 현재 상태에서 시작

대화와 자료에서 목표 직무·세부 분야, 경력·프로젝트, 보유 자료, 지원 단계, 마감과 사용할 수 있는 시간을 파악한다. 정해지지 않은 값은 미정으로 두며 모든 항목을 채우는 설문을 시작하지 않는다.

목표가 불명확하면 다음 행동을 정하는 데 필요한 질문부터 한다. 예: 맡고 싶은 업무가 무엇인지, 지금 검토할 경험이나 자료가 있는지. 이미 목표 공고가 있으면 그 공고를 출발점으로 삼는다. 신입·주니어 등의 수준을 문체나 툴 목록만으로 추정하지 않는다.

경험 정리를 함께 요청받으면 [근거 기록](evidence-record.md)에 맞춰 제공된 정보부터 추출한다. 부족한 정보는 해당 판단과 연결해서 묻는다. 사용자가 말하지 않은 취업 지역·급여·회사 규모·고용 형태 선호를 설정하지 않는다.

## 필요한 단계 연결

| 현재 상황 | 먼저 할 일 | 다음 작업의 입력 |
|---|---|---|
| 공고가 있고 요구를 모름 | 공고 분석 | 우선 요구사항과 확인할 조건 |
| 자료는 있지만 설득력을 모름 | 서류 진단 | 강점 근거와 보완할 위치 |
| 경험이 흩어져 있음 | 제공 자료에서 경험 목록 정리 | 본인 역할·판단·결과·출처 |
| 지원 문항을 작성해야 함 | 문항별 경험 배치 후 작성 | 실제 문항·분량과 사용할 경험 |
| 수정 후 제출 예정 | 지적별 재검토와 관련 서류 일치 확인 | 해결 여부와 남은 확인 사항 |
| 면접 예정 | 공고와 제출본에 기반한 질문·연습 | 증명할 역량과 설명이 약한 주장 |

모든 단계를 순서대로 강제하지 않는다. 필요 자료가 없으면 가능한 단계부터 진행하고 회사 맞춤 평가인지 일반 준비인지 밝힌다.

## 여러 지원 건 비교

사용자가 제공하거나 조사를 요청한 공고를 회사·직무·공고 버전별로 구분한다. 비교 축은 명시 지원 자격, 핵심 업무에 대한 근거, 제출 요구, 확인된 마감, 필요한 보완량, 사용자의 선호다.

‘곧 지원 준비 가능’, ‘보완 후 검토’, ‘조건 확인 필요’처럼 행동 기준으로 정리하고 각 판단의 근거를 붙인다. 합격 확률이나 회사의 비공개 채용 기준으로 순위를 만들지 않는다. 경력·학위 등의 충돌과 확인 불가는 별도로 드러낸다.

최신 공고·마감을 묻거나 지금 지원 가능한지 판단해야 할 때는 실제 공고를 확인한다. 이전에 저장한 공고의 날짜를 현재 유효하다고 가정하지 않는다. 상시채용을 무기한 지원 보장으로 해석하지 않는다. 정확한 마감 시각·시간대가 없으면 추정해 일정에 넣지 않는다.

[직무별 기준](role-criteria.md)에 따라 지원 건마다 필요한 산출물·근거를 따로 정한다. 서로 다른 직군을 비교할 때 기획 포트폴리오의 완성도를 공통 척도로 쓰지 않는다. 전환 지원자는 기존 경험에서 연결되는 역량과 새 직무에서 확인할 차이를 나누고, 모든 경험을 처음부터 다시 만들게 하지 않는다.

## 실행 계획

먼저 제출을 막는 요건·누락과 근거 없는 주장을 확인하고, 다음으로 기존 경험을 잘 설명하는 수정, 여유가 있으면 새 검증·작업을 배치한다. 보완 행동마다 결과물과 완료 기준을 명시한다.

예: ‘시스템 기획 공부’보다 ‘포트폴리오 p4에 하루 재화 획득·소모 가정과 목표 성장 기간의 계산을 연결하고, 계산이 맞는지 확인’이라고 제시한다. 실제 기간은 자료 분량·숙련도·가능 시간에 따라 달라지므로 시간 추정에는 가정을 붙인다.

마감이 임박하면 가능한 수정과 이후 과제로 나눈다. 사용자가 제공한 시간이 부족하면 중요한 항목을 선택하고 무엇이 남는지 밝힌다. 신규 상용 경력이나 대규모 실험을 짧은 기간의 서류 수정처럼 제안하지 않는다.

지원 제출·회사 연락·지원 현황의 외부 서비스 변경은 별도 요청이 있을 때 수행한다. 계획 작성이 실제 지원 실행을 의미하지 않는다.
