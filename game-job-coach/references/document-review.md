# 이력서·포트폴리오와 공고의 정합성 진단

## 최소 입력과 읽기

정합성 진단에는 공고와 하나 이상의 지원 자료가 필요하다. 이력서만 있으면 이력서 기준으로, 포트폴리오만 있으면 해당 자료 기준으로 수행하고 범위를 밝힌다. 공고가 없으면 일반 서류 검토를 진행할 수 있지만 회사별 매칭 평가로 표시하지 않는다.

이력서에서 경력·기간·역할·기여·툴·결과를 추출한다. 포트폴리오에서는 해당 주장을 뒷받침하는 설계·구현·시각 결과물·검증 과정을 확인한다. 텍스트 추출만으로 시각 품질이나 페이지 구성을 평가하지 않는다. 읽을 수 없는 부분은 페이지별로 범위를 남긴다.

자료 간 프로젝트명·기간·역할·성과가 충돌하면 어느 쪽이 맞는지 임의로 고르지 않는다. 충돌 내용을 짚고 확인 전까지 관련 판단을 유보한다.

자료 형식은 직무에 맞춘다. 개발은 코드·구조·측정 기록, 아트·사운드는 실제 확인 가능한 작업물과 제작 기여, QA는 재현·검증 기록, PM·사업·운영은 판단·조정·실행 사례, 데이터는 정의·분석·검증, 현지화는 원문·대상 언어·문맥·수정 근거를 중심으로 본다. 경영지원은 공고에 맞는 업무 사례를 활용한다. 이는 확인 가능한 근거의 예이며 일괄 제출 목록이 아니다. 기밀 자료는 공개 가능한 요약이나 익명화 사례로 범위를 제한한다.

## 요건 대조

공고의 담당 업무와 필수·우대 조건을 구분하고 원래 항목을 추적한다. 복합 요건은 하위 요소를 확인하되 통계나 점수에서 중복 계산하지 않는다. [직무별 기준](role-criteria.md)에서 실제 담당 업무에 해당하는 상세 지침을 읽고 증거를 해석한다. 주된 직무와 함께 보는 업무를 구분하며, 공고에 없는 인접 직무 역량을 미충족으로 추가하지 않는다.

먼저 자료의 종류와 목적을 확인한다. 이력서는 역할·기간·성과의 빠른 파악, 포트폴리오는 판단·과정·결과물의 확인에 집중한다. 긴 포트폴리오의 첫 소개와 핵심 페이지에서 지원 직무에 필요한 근거를 찾을 수 있는지 본다. 분량이나 디자인 취향만으로 품질을 평가하지 않는다.

| 상태 | 판단 기준 |
|---|---|
| 충족 | 해당 요구를 뒷받침하는 구체적인 진술·작업물이 확인됨 |
| 일부 충족 | 요구의 일부나 관련 경험은 확인되지만 핵심 범위·깊이에 차이가 있음 |
| 자료에서 확인 불가 | 근거가 없거나 읽을 수 없거나 충돌하여 판단하기 어려움 |
| 미충족 | 지원자에게 확인된 사실이 명시 요건과 어긋남 |

충족 판단에는 근거의 성격도 적는다. ‘지원자 진술’, ‘문서에 명시’, ‘결과물 직접 확인’을 같은 검증 수준으로 취급하지 않는다. 도구 이름만 있으면 사용 사실의 근거일 수 있지만 숙련도나 실무 성과까지 증명하지는 않는다.

필수·우대 표에 `요건 / 상태 / 근거 위치와 근거 요약 / 차이·확인할 점 / 개선 행동`을 넣는다. 같은 근거를 여러 요건에 사용할 수 있지만 같은 성과를 여러 독립 경험처럼 세지 않는다.

## 피드백의 구체성

중요한 지적은 `관찰한 내용과 위치 → 명시 조건·설명의 정확성에 미치는 영향 → 가장 작은 보완 → 완료 기준`으로 연결한다. 자료에 없는 것과 실제 오류를 구분하고 관찰하지 못한 결함을 만들지 않는다. ‘실무에서는 부족하다’ 같은 평가는 어떤 요구·작업 결과와 어긋나는지 설명할 수 있을 때만 사용한다.

예를 들어 신입의 경제 역기획에 보상 금액만 있다면 ‘수치가 약함’ 대신, ‘성장 목표와 재화 수급 가정이 없어 금액의 적절성을 판단하기 어렵다. 하루 획득·소모량과 목표 도달 기간을 같은 표로 연결하라’고 설명한다. 보완 완료는 계산의 입력 가정과 결과를 추적할 수 있을 때로 둔다. 상용 서비스 성과를 추가하라고 요구하지 않는다.

실제 작업물에서 확인된 판단과 검증은 근거의 깊이로 설명한다. ‘Excel 사용’ 요건 충족과 경제 설계의 타당성은 별개다. 자료가 상세해졌다는 이유만으로 미충족 경력 조건이나 확인하지 못한 실무 숙련도를 충족으로 바꾸지 않는다.

재검토 요청이면 [수정 전후 검토](revision-review.md)를 먼저 적용한다. 이전 평가의 오류나 새 자료에 따른 판단 변경도 이유를 밝혀 정정한다.

## 점수는 요청받았을 때만

기본 결과는 상태와 근거 중심이다. 자의적인 항목별 충족률이나 합격 확률을 만들지 않는다. 숫자를 요청받으면 아래 방식을 공개해 ‘확인된 자료에 대한 참고 점수’와 ‘평가 가능 범위’를 함께 계산한다.

- 원래 필수 항목의 가중치 2, 우대 항목의 가중치 1을 기본 예시로 사용한다. 회사의 실제 배점이 아니며 사용자 지정 기준이 있으면 그 기준을 따른다.
- 충족 1, 일부 충족 0.5, 미충족 0으로 둔다. ‘자료에서 확인 불가’는 점수 분모·분자에서 제외한다.
- 참고 점수 = `100 × Σ(평가 가능한 항목의 가중치 × 상태값) / Σ(평가 가능한 항목의 가중치)`.
- 평가 가능 범위 = `100 × Σ(평가 가능한 항목의 가중치) / Σ(전체 항목의 가중치)`.
- 전부 확인 불가이면 점수는 ‘산출 불가’, 범위는 0%다. 공고 자체가 불완전해 전체 요건을 알 수 없으면 전체 기준 점수는 산출하지 않는다.
- 실제 계산 도구로 합계와 반올림을 확인한다. 기본 항목별 가중치는 제시한 표에서 추적 가능해야 한다.
- 학위·경력·고용 조건 등 명시된 지원 자격과의 충돌은 점수 앞에 별도로 밝힌다. 높은 평균으로 해당 미충족을 덮지 않는다. 채용사의 예외 허용 여부는 확인 필요다.

일부 확인된 항목만으로 점수가 높아져도 전체 적합도가 높다고 해석하지 않는다. 담당 업무는 별도 대조하며, 필수·우대와 중복되는 항목을 점수에 추가하지 않는다.

## 결과와 우선순위

먼저 현재 자료에서 확인되는 강점과 가장 중요한 차이를 요약한다. 이어 필수·우대 대조표, 핵심 업무 수행 근거, 수정 우선순위를 제시한다.

개선 행동은 ‘구체적으로 쓰기’ 대신 실제 수정 위치와 내용을 지정한다. 예: ‘프로젝트 역할 설명에 본인이 결정한 보상 규칙과 검증 방법 추가’. 문장만 고칠 일, 기존 경험을 더 확인할 일, 새 작업이 필요한 일을 구분한다. 이미 요구를 설명하는 근거가 충분하면 그 부분을 유지하도록 한다. 새 영상·프로젝트·상용 지표를 추가할 때는 기존 자료로 해결되지 않는 이유가 있어야 한다.

공고와의 관련성, 근거의 설득력, 적은 수정으로 개선되는 정도를 고려해 우선순위를 정한다. 명시 조건 충돌과 사실·계산 오류를 먼저 다루고, 핵심 근거의 부족, 선택적인 표현 개선을 구분한다. 자료 전체를 칭찬하거나 비판하는 일반론보다 해당 지원 건에서 중요한 수정에 집중한다.

구성 개선을 요청받으면 공고에 직접 연결되는 작업물과 본인 판단·기여를 앞에서 찾을 수 있도록 배치안을 제안한다. 유지·이동·축약할 위치와 이유를 짚되, 페이지 수를 보편적인 정답으로 정하거나 검증 한계·팀 기여 표기를 보기 좋게 만들려고 삭제하지 않는다. 자료를 직접 보지 못했다면 구성안의 판단 범위를 밝힌다.

마감이 주어졌다면 [취업 준비 계획](career-plan.md)의 시간 배분 원칙을 적용한다. 주어진 시간에 할 수 있는 수정과 이후 진행할 검증을 구분하고, 제출 일정이나 실제 경력을 문서 수정으로 해결할 수 있는 것처럼 제시하지 않는다.

최종 파일이나 제출 가능 여부를 묻는 경우에는 [제출 점검](submission-check.md)을 함께 적용한다. 내용 검토만 끝낸 상태와 파일·열람 조건까지 확인한 상태를 구분한다.
