# 수정 전후 검토와 피드백 추적

이력서·포트폴리오·자소서 수정본, 면접 재답변, 이전 피드백의 반영 여부를 검토할 때 사용한다. 요청받은 범위에서 비교하고 관련 없는 문서를 새로 전면 평가하지 않는다.

## 비교 기준 확인

이전 지적과 원본 또는 그 지적이 인용한 근거, 수정본, 목표 공고·문항을 확인한다. 파일명·버전·페이지·섹션을 구분한다. 같은 파일명이면 실제 내용으로 비교한다. 최신 수정 시각만으로 제출본을 선택하지 않는다.

이전 자료가 없으면 현재 자료만으로 진단하고, 개선 여부는 비교 불가라고 밝힌다. 원본 전체가 없어도 이전 피드백에 충분한 근거와 완료 기준이 있으면 그 지적 범위에서는 재검토할 수 있다. 읽지 못한 부분을 개선됐다고 추정하지 않는다.

공고·문항·지원 직무가 달라졌으면 기존 지적의 적용 여부부터 확인한다. 새 공고에서 중요하지 않아진 항목은 ‘적용 범위 변경’으로 설명하며 수정으로 해결했다고 기록하지 않는다.

## 지적별로 판단

중요 지적에 I01 같은 ID를 붙이고 기존 ID를 유지한다. 문장 수만큼 새 ID를 만들지 않는다. 다음 내용을 필요한 만큼 기록한다.

`지적 ID / 이전 문제와 근거 / 완료 기준 / 수정본의 실제 변경과 위치 / 상태 / 남은 행동`

| 상태 | 판단 |
|---|---|
| 해결 | 원래 문제를 해소하는 근거·변경을 확인했고 연관 문서와도 모순되지 않음 |
| 일부 해결 | 완료 기준의 일부만 충족. 남은 요소를 특정할 수 있음 |
| 미해결 | 같은 문제가 유지되거나 표현만 바뀌어 판단 근거가 늘지 않음 |
| 확인 불가 | 비교 근거·해당 페이지·필요 사실이 없어 해소 여부를 판단할 수 없음 |

이 상태는 공고의 ‘충족·일부 충족·미충족·확인 불가’와 다른 개념이다. 과장된 경력 표현을 바로잡아 지적이 해결되어도 지원 자격 미충족은 남을 수 있다.

문제를 지적한 문장을 삭제한 경우, 과장이나 중복 표현의 제거가 목적이었다면 해결로 볼 수 있다. 필수 근거가 필요했던 경우에는 문장 삭제만으로 해결하지 않는다. 새로 제시된 사용자 진술을 사용할 때는 근거의 성격을 유지하며 외부 검증을 임의로 요구하지 않는다.

## 새 불일치 점검

- 기간·역할·팀 규모·툴·수치·측정 기준이 다른 페이지나 자소서·이력서와 일치하는가?
- 계획·제안이 실제 실행·출시·운영 성과로 바뀌었는가? 바뀌었다면 새 사실과 근거가 제공됐는가?
- 팀 성과가 개인 성과가 됐거나 상대 변화율과 퍼센트포인트가 혼동됐는가?
- 자소서가 실제 질문·글자 수를 충족하는가? 면접 재답변은 표현뿐 아니라 핵심 근거도 보완됐는가?

새 문제는 기존 지적과 별도로 기록하되, 같은 원인·완료 기준을 가진 문제가 다른 문서에서도 발견되면 기존 지적 ID에 위치와 근거를 추가한다. 하나의 성과 과장 문제를 문서마다 별개 지적으로 중복 집계하지 않는다. 독립된 수정과 완료 기준이 필요한 경우에만 새 ID를 만든다. 자료가 추가되어 원래 평가가 잘못됐음을 알게 되면 기존 평가를 정정하고 이유를 밝힌다. 과거 판단을 유지하려고 새 근거를 무시하지 않는다.

## 결과와 후속 행동

먼저 개선된 점과 여전히 중요한 문제를 요약하고 지적별 비교를 제시한다. 사소한 문장 수정은 묶어서 설명한다. 다음 행동은 중요도 순으로 최대 3개와 완료 기준을 제시한다. 단순 지적 개수나 평균 점수 감소만으로 제출 준비가 끝났다고 결론내리지 않는다.

저장 요청이 있으면 [근거 기록](evidence-record.md)의 지원 건 기록에 검토 이력을 이어 쓴다. 현재 검토 상태를 갱신하면서 이전 판단과 변경 이유를 남긴다. 확인하지 않은 지적을 자동으로 해결 처리하지 않는다.
