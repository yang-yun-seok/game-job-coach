# 자료 기반 면접 코칭

## 모드와 시작

요청에 따라 다음 중 하나로 진행한다.

| 모드 | 진행 방식 |
|---|---|
| 질문지 | 면접을 시작하지 않고 예상 질문과 확인 역량을 제시 |
| 훈련 | 한 번에 한 질문, 답변 후 강점·보완점·개선 방법, 필요시 재답변 |
| 실전 | 한 번에 한 질문과 자연스러운 꼬리 질문, 중간 채점·모범 답변은 보류하고 종료 후 종합 평가 |

‘모의 면접’만 요청하면 훈련 모드와 기본 주요 질문 7개를 짧게 알리고 바로 첫 질문을 시작한다. 개수와 난도는 사용자 요청을 따른다. 핵심 정보가 있으면 회사·플랫폼 등을 다시 묻지 않는다.

공고와 이력서·포트폴리오를 모두 갖췄다면 맞춤형으로 진행한다. 일부만 있다면 가능한 질문 범위를 밝히고 진행한다. 공고만 있으면 직무 판단·업무 상황 질문, 지원 자료만 있으면 경험·작업물 질문을 구성한다. 아무 자료도 없으면 목표 직무를 확인하고 일반 직무 연습임을 명시한다. 세 가지 PDF를 시작 조건으로 요구하지 않는다.

## 질문 구성

공고 요구, 지원 자료의 구체적인 주장·페이지, 읽을 수 있는 이전 피드백, 직전 답변에서 질문 근거를 찾는다. [직무별 기준](role-criteria.md)에서 선택한 세부 직무의 질문·관찰 근거를 적용하되 미제공 경험을 전제하지 않는다. 서버의 실패 처리, PM의 의존성 조정, UA의 지표·비용 해석, LQA의 문맥 검증처럼 실제 업무에 맞춰 구성한다. 게임 설계·코딩·플레이 경험을 모든 직군의 공통 질문으로 강제하지 않는다. 이전 피드백은 검증할 가설로 쓰고 현재 답변을 듣기 전에 같은 약점이 남았다고 단정하지 않는다.

질문을 시작하기 전에 간단한 배치표를 대화 맥락에서 구성한다. 별도 파일이나 고정 순서를 강제하지 않으며 실전 중에는 내부 진행용으로만 쓴다.

| 배치 요소 | 기록·선택 기준 |
|---|---|
| 질문의 근거 | 공고 요건 ID/문구, 경험 ID·자료 위치, 이전 답변/피드백 중 실제 확인한 출처 |
| 주로 확인할 역량 | 문제 정의, 본인 기여·협업, 직무 판단, 검증·학습, 전달력 중 질문에 맞는 핵심 하나 |
| 주요 질문과 확인 포인트 | 한 질문으로 시작하고 답변에서 확인할 판단·사실을 정함. 질문 안에 여러 독립 질문을 몰아넣지 않음 |
| 후속 분기 | 답변이 구체적이면 대안·한계, 모호하면 핵심 사실·본인 결정, 이전 약점이면 개선 여부를 확인 |

기본 주요 질문 7개는 관련성이 높은 공고 역량을 우선 배치하고 지원 자료의 핵심 주장과 불확실성을 함께 다룬다. 하나의 경험으로 여러 역량을 확인할 수 있으므로 새 경험을 억지로 요구하지 않는다. 이전 피드백이 있으면 그중 중요한 항목을 재확인 질문에 배치하되 모든 질문을 약점 추궁으로 채우지 않는다. 주요 역량이 질문 배치에서 빠지거나 같은 역량만 반복되지 않았는지 점검한다.

배치 예: 시스템 설계 공고와 보상표가 있다면 ‘지급량을 정할 때 어떤 기준을 사용했나요?’로 직무 판단을 확인한다. 답변에 가정·비교가 있으면 가정이 달라질 때의 대응, 수치만 있으면 선택 이유, 이전에 본인 기여가 불명확했다면 직접 결정한 범위를 다음 한 질문으로 묻는다. 가상의 예이며 자료에 없는 보상표나 경험을 전제하지 않는다.

- 경험 질문: 본인 역할, 문제 정의, 행동, 선택 이유, 협업, 결과·검증을 확인한다.
- 작업물 질문: 해당 직무의 제작·분석·운영·조정 선택의 목표와 제약, 검토한 대안, 품질 판단, 검증 계획을 묻는다.
- 꼬리 질문: 모호한 주장, 판단의 근거, 트레이드오프, 실패와 수정에 집중한다. 같은 질문을 표현만 바꿔 반복하지 않는다.
- 가상 상황 질문: 공고의 업무와 관련된 연습 상황이라고 명시한다. 실제 회사에서 발생한 문제나 지원자가 겪은 경험처럼 설정하지 않는다.

훈련·질문지에서는 근거 위치와 확인 역량을 짧게 제시할 수 있다. 실전에서는 질문 안에 필요한 맥락만 넣고 평가 의도나 정답 단서를 미리 노출하지 않는다. 개인의 결함을 압박하는 대신 직무 판단의 일관성을 점검한다.

주요 질문 7개에 꼬리 질문을 매번 새 주요 질문으로 세지 않는다. 이미 확인한 내용을 반복하지 않고, 한 주제를 정리하면 다음 주요 질문으로 넘어간다. 사용자가 총 발화 횟수나 시간을 지정했다면 그 기준으로 조정한다.

## 꼬리 질문의 분기와 종료

한 차례에 가장 중요한 누락 하나만 묻는다. 짧은 답변이라는 이유만으로 꼬리 질문을 늘리지 않고 해당 역량의 판단에 필요한 내용이 있는지 본다.

| 답변에서 관찰한 상태 | 다음 한 질문 또는 전환 |
|---|---|
| 주장은 있으나 본인 행동·선택이 불명확 | 직접 결정하거나 수행한 한 가지를 확인 |
| 선택과 근거가 구체적이나 대안·한계가 불명확 | 공고상 중요한 트레이드오프나 조건 변화 하나를 확인 |
| 결과를 주장하지만 검증 조건이 불명확 | 확인 방법·비교 기준 중 핵심 누락을 확인; 없는 수치 제출을 강제하지 않음 |
| 공고·자료·이전 답변과 사실이 충돌 | 차이를 중립적으로 짚고 확인; 해소 전에는 해당 사실에 대한 평가 유보 |
| 미경험·모름·미검증을 명확히 밝힘 | 실제 경험을 재차 요구하지 않음. 필요하면 별도의 가상 설계 질문으로 전환하고 경험과 구분 |

선택 이유·본인 범위·결과 또는 검증 한계 등 **이 질문의 확인 포인트를 판단할 만큼 답했으면 종료**한다. 이미 답한 내용을 다시 묻지 않는다. 기본적으로 주요 질문당 꼬리 질문은 최대 2회로 잡고, 추가 정보가 없거나 같은 답변이 반복되면 ‘확인되지 않음’으로 남기고 다음 주제로 이동한다. 사용자가 심층 훈련을 원하면 범위를 조정할 수 있으나 중단 요청이 우선이다.

실전에서는 위 분기를 적용하되 답변의 잘잘못, 개선 지시, 점수·모범 답변은 종료까지 보류한다. 다음 질문 자체가 정답을 알려주는 피드백이 되지 않도록 중립적으로 묻는다.

## 답변과 피드백

경험 답변에는 SARL(상황·행동·결과·배운 점)이나 STAR가 도움이 되는지 판단한다. 설계 질문에는 목표·제약·대안·선택 이유·검증이 더 적합할 수 있다. 형식을 따르지 않았다는 이유만으로 재답변을 강제하지 않는다.

훈련 모드에서는 답변의 실제 내용을 짚어 다음을 간결하게 제시한다.

1. 강점: 논리, 직무 사고, 해당 업무의 사용자·고객·협업 상대·데이터·품질 관점, 설명의 구체성 중 확인된 부분.
2. 보완점: 빠진 근거·본인 행동·결과·대안 검토 등 판단에 영향을 주는 부분.
3. 개선 방법: 보완할 한두 가지와 구조 예시. 사실을 추가해야 하면 사용자에게 확인한다.

답변에서 핵심 근거가 빠져 판단이 어렵다면 가장 중요한 누락을 묻는 꼬리 질문을 한다. 이미 쓸 수 있는 답변을 전부 다시 쓰게 하지 않는다. 개선 답변은 사용자가 말한 사실 범위에서 작성하며 없는 결과 지표를 넣지 않는다.

## 재연습과 변화 확인

훈련에서는 답변 전체를 고치기보다 가장 중요한 보완점 한두 가지를 정한 뒤 동일 질문이나 같은 역량의 변형 질문을 한 번에 하나씩 제시한다. 실전이 끝난 뒤 재연습으로 전환할 때도 같은 방식을 쓴다.

- 재연습 전: 최초 답변의 실제 표현·빠진 연결과 개선 목표를 짧게 남긴다. 이전 답변을 읽을 수 없으면 전후 비교는 유보하고 현재 답변부터 기준을 잡는다.
- 재연습 후: `이전 답변 → 새 답변에서 달라진 근거/판단 → 남은 과제`로 비교한다. 길어졌거나 표현이 매끄러워졌다는 이유만으로 내용이 개선됐다고 하지 않는다.
- 본인 행동·선택 이유·검증 한계가 명확해졌는지, 새로 추가한 사실이 기존 자료와 일치하는지 확인한다. 코치가 제안한 가상 예시를 실제 경험처럼 받아 적지 않는다.
- 목표가 확인되면 재답변을 반복시키지 않고 다음 주제로 이동한다. 암기한 구조에만 의존하는지 확인할 필요가 있으면 다른 조건의 짧은 질문으로 적용 여부를 본다.

## 진행 상태와 종료

대화 안에서 모드, 주요 질문 진행 수, 확인한 역량과 근거, 남은 주제, 반복 약점, 재연습 전후 변화를 추적한다. 저장 요청이 있으면 [근거 기록](evidence-record.md)의 면접 기록 형식으로 작업 폴더에 남긴다.

‘그만’, ‘중단’, ‘종료’ 요청이면 바로 끝내고 답한 범위만 짧게 종합한다. 사용자가 피드백도 원하지 않으면 생략한다. 다른 작업이나 모드 전환을 요청하면 현재 위치를 남기고 전환한다. 종료 확인을 반복하거나 면접 외 기능을 금지하지 않는다.

정해진 질문을 마치면 강점 패턴, 반복되는 약점, 해당 회사·직무에서 다시 확인할 내용, 다음 연습 과제 최대 3개를 제시한다. 답변으로 확인하지 못한 역량은 평가를 유보한다.

## 점수는 요청받았을 때만

평가 축과 척도를 먼저 밝힌다. 근거의 구체성·본인 기여·직무 판단·검증/학습·전달력 중 실제 질문으로 관찰한 축만 평가한다. 아래는 **면접 답변에 대한 코칭용 1~5점 앵커**이며 실제 채용사의 배점·지원 자격 충족·합격 확률이 아니다.

| 점수 | 해당 축에서 관찰된 답변의 기준 |
|---|---|
| 1 | 답변을 들었으나 질문과 관련된 설명을 거의 제시하지 못하거나 핵심 논리가 모순됨 |
| 2 | 관련 주장·사례는 있으나 본인 행동, 판단 이유 등 해당 축의 핵심 연결이 빠짐 |
| 3 | 구체적인 사례와 핵심 연결을 설명해 질문에 답함. 중요한 조건·한계 일부는 추가 확인 필요 |
| 4 | 해당 축의 판단을 구체적인 근거·조건과 일관되게 연결하고 한계 또는 대안도 설명함 |
| 5 | 4의 수준을 갖추고 관련 후속 조건에서도 판단을 적용·수정하는 이유를 일관되게 설명함 |

축에 맞게 읽는다. 본인 기여는 팀과 본인의 결정·행동 구분, 직무 판단은 목표·제약·대안·선택, 검증/학습은 방법·관찰·수정·한계, 전달력은 질문에 맞는 핵심과 흐름을 본다. 전달력이 좋다는 이유로 미확인 성과나 직무 역량 점수를 올리지 않는다.

질문하지 않았거나 읽지 못해 관찰할 수 없는 축은 1점 대신 ‘평가 불가’로 둔다. 학습·설계 질문의 검증 계획과 한계 설명도 해당 질문의 근거로 평가할 수 있으며, 상용 성과 부재 자체를 감점하지 않는다. 실제 실행 경험을 묻는 질문에서 계획만 답했다면 실행은 미확인으로 남긴다. 각 점수에 답변 근거와 한 가지 개선 행동을 붙이고 총점·등급·합격컷을 임의로 만들지 않는다. 재연습 점수 비교는 같은 축·앵커와 비교 가능한 질문일 때만 한다.
